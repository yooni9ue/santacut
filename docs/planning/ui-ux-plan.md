# 산타컷 UI·UX 기획

문서 버전: 0.1 / 작성일: 2026-11-15

기존 [백엔드 설계](../../backend/docs/backend-design.md)를 바탕으로 한 MVP 화면·사용자 흐름 제안이다. 아래 화면 구성과 카피는 구현 전 초안이다.

현재 메인 화면의 시각 기준은 [디자인 방향](../design/visual-direction.md)을 참고한다. 이 문서의 시각·인터랙션 절은 초기 기획안을 보존한 것으로, 현재 화면과 차이가 있을 수 있다.

## 1. 경험의 목표

사용자가 자신의 기록으로 재미있는 산타 판정을 받고, 점수와 선물 도착일을 친구에게 공유한다. 핵심 보상은 **나에 대한 유쾌한 판정 + 순위 때문에 달라지는 선물 도착일**이다.

모바일 우선으로 설계한다. 가입보다 결과 예시를 먼저 보여주고, 외부 데이터 준비의 수고를 시작 전에 알려준다. 파일 준비를 마친 시점에 닉네임과 지역을 받는다. 이는 기존 기획의 등록 우선 흐름을 바꾸는 UX 제안이며 익명 세션은 업로드 전 등록 단계에서 발급한다.

서비스 화면에서 원문 대화, 상대방 이름, 정확한 출발지, 앞사람의 지역은 노출하지 않는다. 실제 배송을 제공하지 않는 오락용 시뮬레이션임을 첫 화면과 결과 화면에 짧게 안내한다.

## 2. 전체 사용자 흐름

### 첫 방문

홈 → 데이터 출처 선택 → 준비 안내 → 파일 선택·사전 확인 → 닉네임·지역 등록 → 분석 내용 확인·동의 → 업로드·심사 → 결과 → 공유

카톡 사용자는 파일 사전 확인 단계에서 본인 화자를 선택한다. 등록 전 파일 확인은 가능한 범위에서 브라우저 내부에서 수행하며, 원본을 서버로 전송하는 시점은 동의 후로 명확히 구분한다. 브라우저에서 대용량 파일 전체를 읽거나 파싱하지 않도록 제한하고, 실제 유효성 판정은 서버에서도 수행한다. 브라우저 사전 확인이 어려운 형식은 지원 안내를 제공하며 등록 이전에 서버 업로드를 몰래 수행하지 않는다.

### 파일을 이미 가진 방문자

홈의 `파일이 이미 있어요` → 출처 선택 → 파일 선택 → 이후 동일

### 재방문

홈 → 유효한 세션과 작업 상태 확인 → 진행 중이면 심사 화면, 성공 결과가 있으면 결과 화면으로 연결한다. 홈에는 `내 결과 보기`와 `다시 심사받기`를 제공한다. 분석 실패 후에는 이전 정상 결과를 계속 볼 수 있다.

### 공유 링크 방문

공유 결과 → `나도 산타컷 받아보기` → 홈/출처 선택. 공유한 사람의 업로드 데이터와 상세 항목별 근거는 공개하지 않는다.

### 데이터 준비 중 이탈 후 복귀

출처·안내 단계는 개인정보 없이 기기에 저장한다. 홈에 `이어서 준비하기`를 제공한다. 브라우저가 파일을 유지한다고 가정하지 않으며 파일 재선택이 필요하면 안내한다. 명시적으로 화면을 이동하거나 사용자가 재개할 때 이전 상태를 복구하고, 외부 서비스 방문 여부를 감시하지 않는다.

## 3. 화면 목록과 핵심 행동

| 화면 | 사용자의 질문 | 핵심 정보 | 주 행동 |
| --- | --- | --- | --- |
| 홈 | 이게 뭐고 재미있을까? | 결과 예시, 이용 과정, 데이터 준비 필요 | 내 산타 점수 알아보기 |
| 출처 선택 | 어떤 기록을 쓸까? | 카톡/인스타 지원 범위와 준비 방식 | 출처 선택 |
| 준비 안내 | 파일을 어떻게 구하지? | 기기·출처별 단계, 필요한 형식 | 파일 준비됐어요 |
| 파일 확인 | 이 파일로 가능할까? | 파일명·크기·형식, 카톡 본인 화자 | 이 파일로 계속 |
| 참가 정보 | 어떤 이름과 지역으로 참여할까? | 닉네임, 시·도/시·군·구 | 다음 |
| 분석 확인 | 무엇을 보내고 공개할까? | 출처·본인·지역, 원본 처리, 공개 범위 | 동의하고 심사 시작 |
| 심사 중 | 지금 어디까지 됐지? | 실제 작업 상태, 이탈·복귀 안내 | 결과 자동 표시 / 상태 다시 확인 |
| 내 결과 | 나는 몇 점이고 언제 받을까? | 판정·점수·순위·ETA·심사평 | 결과 공유하기 |
| 랭킹 | 다른 사람들과 비교하면? | 내 위치, 전체 순위, 계산 기준 시각 | 내 결과 보기 |
| 공개 결과 | 친구는 어떤 판정을 받았지? | 공유 당시 카드·시각 | 나도 산타컷 받아보기 |

홈·랭킹·내 결과 사이에는 텍스트 링크를 제공한다. 시작 단계에서는 고정 하단 탭을 두지 않고 뒤로가기와 한 개의 주요 버튼에 집중한다. 준비 과정에는 `기록 준비 → 참가 정보 → 산타 심사`의 3단계 진행 표시를 사용한다. 실제 업로드 완료 전 심사가 시작된 것처럼 표시하지 않는다.

## 4. 화면별 상세

### 4.1 홈 `/`

첫 화면 구성:

1. 산타컷 로고와 `내 결과` 링크(유효한 결과가 있을 때).
2. 제목: `너 올해 산타컷 통과 가능?`
3. 설명: `내 기록으로 받는 산타 판정. 점수부터 선물 도착 예정일까지.`
4. 결과 카드 예시: `예시 결과`를 명시하고 가상의 닉네임·97.82점·판정·도착일을 보여준다. 실제 이용자의 결과나 실시간 통계로 오인하게 만들지 않는다.
5. 주 버튼: `내 산타 점수 알아보기`.
6. 보조 링크: `파일이 이미 있어요`, `전체 랭킹 보기`.
7. 신뢰 안내: `카톡 대화 또는 지원되는 인스타 활동 파일이 필요해요. 원본은 공개되지 않아요.`
8. 3단계 이용 방법과 `실제 선물 배송을 제공하지 않는 재미용 서비스입니다.`

데이터 준비 시간을 포함한 총 소요 시간을 확정적으로 약속하지 않는다. 검증되지 않은 참여자 수, 가짜 순위, 가짜 후기를 넣지 않는다.

### 4.2 출처 선택 `/start`

제목: `어떤 기록으로 심사받을까요?`

카톡·인스타를 각각 큰 선택 카드로 배치한다. 카드에는 사용할 데이터, 준비 방법, 지원 상태를 표시한다. 미지원 출처는 선택할 수 없게 하고 이유를 설명한다. 실제 인스타 샘플 검증 전에는 이용 가능으로 표시하지 않는다.

하단 도움말: `한 가지 기록만 제출하면 돼요. 두 종류를 제출해도 점수가 합산되지 않아요.`

선택 후 바로 해당 준비 안내로 이동한다. 단순 선택을 위해 추가 확인 버튼을 두지 않는다.

### 4.3 데이터 준비 `/prepare/[source]`

제목: `심사에 쓸 파일을 준비해 주세요`

- `파일 준비 방법`과 `이미 파일이 있어요`를 상단에 제공한다.
- 카톡: iOS·Android·PC 중 검증된 경로를 탭으로 구분한다. 내보낸 대화의 지원 형식과 본인 화자 선택 필요성을 설명한다.
- 인스타: JSON 선택, 필요한 항목과 분석 기간을 설명한다. 생성 대기가 발생할 수 있음을 외부 이동 전에 안내한다.
- 실제 지원 형식, 최대 20MB, 분석 범위 최근 90일·최대 2,000개 이벤트를 보여준다. 제한은 서버 정책과 동기화한다.
- 번호가 붙은 짧은 단계와 필요한 경우 기기별 이미지 안내를 제공한다.
- 외부 이동 버튼은 `인스타그램에서 내보내기 열기`처럼 이동 목적을 명시하고 새 창임을 알린다.
- 하단 주요 버튼: `파일 준비됐어요`.

모바일에서 준비가 어려운 출처에는 검증된 PC 준비 방법을 안내한다. 기기 간 익명 세션 복구를 지원하는 것처럼 표현하지 않는다.

### 4.4 파일 확인 `/upload`

모바일은 파일 선택 버튼, 데스크톱은 동일 버튼과 드래그 영역을 제공한다. `이 단계에서는 파일을 서버로 보내지 않아요`를 실제 동작과 일치할 때만 표시한다.

선택 후 파일명·크기·출처와 `파일 바꾸기`를 보여준다. 검증 상태는 `확인 중 → 준비 완료 / 확인 필요`로 표시한다. 검증 전 성공 표시를 보여주지 않는다.

카톡과 인스타그램 모두 대화 참여자 중 `이 대화에서 나는 누구인가요?`를 선택하게 한다. 인스타그램 `message_1.json`에는 소유자 표시가 없기 때문이다. 자동 추정만으로 본인을 확정하지 않는다. 참여자 이름은 이 화면에만 노출한다. 점수는 본인 말만 매기지만 상대 메시지도 맥락으로 Google Gemini에 보내고(이름은 `상대`로 바꿈), 채점이 끝나면 지운다고 안내한다(동의 문구는 [API 연동 가이드](../api/frontend-api-guide.md) §6.1). 메시지 본문 미리보기는 기본 제공하지 않는다. 지원 파서가 참여자를 식별할 수 없으면 임의로 채점하지 않는다.

주 버튼: `이 파일로 계속`. 파일·본인 화자 확인이 끝나기 전에는 비활성화하고 이유를 인접 텍스트로 제공한다.

### 4.5 참가 정보 `/join`

닉네임과 지역을 한 화면에서 입력한다.

- 닉네임: 2~16자, 한글·영문·숫자·밑줄. 입력을 멈춘 뒤 가용성을 확인하되 최종 등록 전까지 예약된 것으로 표현하지 않는다.
- 중복 오류: `이미 사용 중인 닉네임이에요. 다른 이름을 입력해 주세요.`
- 지역: 시·도 선택 → 시·군·구 선택. 구가 없는 지역을 지원한다. 상위 지역 변경 시 하위 선택을 초기화한다.
- 설명: `상세 주소는 받지 않아요. 선택한 지역의 대표 지점을 기준으로 도착일을 계산해요.`
- 공개 범위: `닉네임은 랭킹과 공유 결과에 표시돼요. 선택한 지역은 기본 공개되지 않아요.`

주 버튼: `다음`. 등록 중 중복 제출을 막고, 서버의 닉네임 충돌 오류를 해당 입력란에 연결한다. 기존 참가자의 재심사는 등록 화면을 반복하지 않고 확인 화면에서 프로필을 보여준다.

### 4.6 분석 확인 `/review`

전송 직전 확인 화면이다. 선택한 출처·파일명·본인 화자·닉네임·지역을 요약하고 각 항목 수정 링크를 제공한다.

필수 고지:

- 어떤 기록과 기간이 분석되는지.
- AI 처리를 위해 고른 대화방의 최근 90일 대화가 상대방 메시지까지 Google Gemini로 전송된다는 사실과 보관 정책(상대방 이름은 `상대`로 바꿔 보내고, 대화 내용은 채점이 끝나면 지운다). 문구 제안은 [API 연동 가이드 §6.1](../api/frontend-api-guide.md)에 있다.
- 원본은 작업 종료 후 삭제하며 중단 작업도 업로드 후 최대 24시간 안에 정리한다는 정책.
- 공개되는 것은 닉네임·점수·순위·도착 예정일·판정이라는 점.
- 재미용 판정이며 실제 인성 평가·선물 배송이 아니라는 점.

필수 동의는 목적별로 알아볼 수 있게 표시하고 기본 체크하지 않는다. 구체적인 동의 문구와 법적 근거는 출시 전에 검토한다. 불필요한 마케팅 동의를 추가하지 않는다.

주 버튼: `동의하고 심사 시작`. 클릭 후 실제 전송 상태를 보여준다. 이때부터 새로고침·창 닫기에 따라 업로드가 중단될 수 있음을 구분한다. 업로드와 서버 접수가 완료된 뒤에는 돌아와 결과를 볼 수 있다고 안내한다.

### 4.7 심사 중 `/analysis/[id]`

업로드는 실제 전송량을 얻을 수 있을 때만 퍼센트를 표시한다. 서버 분석 단계에는 임의 퍼센트·가짜 카운트다운을 쓰지 않는다.

| 서버 상태 | 화면 문구 |
| --- | --- |
| 업로드 중 | 기록을 보내고 있어요 |
| validating | 파일 형식을 확인하고 있어요 |
| queued | 산타 심사를 기다리고 있어요 |
| analyzing | 산타가 기록을 읽고 있어요 |
| 성공 후 순위 계산 대기 | 심사가 끝났어요. 순위와 도착일을 계산하고 있어요 |

장식 애니메이션과 상태 텍스트를 함께 제공한다. 애니메이션 줄이기 설정을 존중한다. 완료 시 자동으로 내 결과로 이동한다.

서버 접수 후 안내: `이 창을 닫아도 심사는 계속돼요. 같은 브라우저에서 다시 확인해 주세요.` 알림을 구현하지 않았다면 푸시·메일이 온다고 약속하지 않는다.

오래 걸리는 경우 `평소보다 시간이 걸리고 있어요`와 `상태 다시 확인`을 제공한다. 새 분석을 자동으로 생성하지 않는다. 실패하면 사용자 행동으로 재시도하며, 유효한 이전 결과가 있으면 함께 연결한다.

### 4.8 내 결과 `/result`

화면의 우선순위:

1. 판정명: `산타 친자 의혹` 같은 한 줄.
2. 점수: `97.82점` — 항상 소수점 둘째 자리.
3. 짧은 심사평 — 원문·상대방 개인정보 인용 없음.
4. 통합 순위와 선물 도착 예정일 — 첫 화면에서 확인 가능하게 배치.
5. `결과 공유하기` 주요 버튼.
6. 항목별 결과, 산정 방식, 전체 랭킹, 재심사, 지역 변경, 내 데이터 삭제.

도착일 표현 예: `12월 26일 오전 12:09 도착 예정`. 다음 해로 넘어가면 연도를 반드시 표시한다. 계산 시각과 `미리보기 / 시즌 확정` 상태를 함께 제공한다.

배송 설명: `산타는 점수 순서대로, 하루 6시간만 움직여요. 참여자가 늘면 출발 전 도착 예정일이 바뀔 수 있어요.` 정확한 출발지나 앞사람의 지역·이동 경로는 노출하지 않는다.

공동 순위는 `공동 2위`로 표시한다. 도움말에 `같은 순위여도 배송 순서에 따라 도착 시간이 다를 수 있어요`를 제공한다. 실제 참가자 수를 받기 전 상위 비율을 만들어 표시하지 않는다.

점수는 있으나 첫 랭킹 스냅샷이 아직 없으면 점수·판정을 먼저 표시하고 순위·ETA는 `계산 중`으로 둔다. 기존 스냅샷이 있으면 그 스냅샷의 점수·순위·ETA를 묶어서 보여주고 새로운 심사 결과가 반영 중임을 별도로 알린다. 서로 다른 버전의 점수와 순위를 같은 결과로 섞지 않는다.

항목별 점수는 펼쳐보기로 제공한다. 가중치와 근거 부족 처리 정책이 확정된 뒤 공개한다. 근거 이벤트 ID나 대화 원문을 결과 화면에 노출하지 않는다.

재심사 전 안내: `새 심사가 성공하면 현재 결과가 교체돼요. 실패하면 지금 결과가 유지돼요.` 지역 변경은 시즌 동결 전에만 제공한다. 동결 후에는 수정 버튼 대신 정책에 맞는 안내를 표시한다.

### 4.9 랭킹 `/ranking`

- 시즌명·참가자 수·계산 시각·미리보기/확정 상태.
- 내 순위를 상단 별도 카드로 보여준다.
- 행 구성: 순위 / 닉네임 / 점수. 도착일은 공간이 충분할 때 보조 정보로 제공한다.
- 첫 화면에 상위 참가자를 표시하고 `더 보기`로 cursor 페이지네이션한다.
- 닉네임을 눌러도 비공개 개인 결과로 이동하지 않는다. 공개 공유 페이지 연결은 명시적인 공개 정책이 있을 때만 제공한다.
- 지역·원문·출처별 경쟁 부문은 표시하지 않는다. MVP는 단일 통합 랭킹이다.
- 빈 상태: `아직 산타 심사를 마친 사람이 없어요` + `첫 심사 받기`.

### 4.10 공유

내 결과의 `결과 공유하기`를 누르면 카드 미리보기와 다음 행동을 제공한다.

- 기기 기본 공유: 브라우저 지원 시 사용.
- 링크 복사: 복사 성공·실패를 명확히 표시.
- 이미지 저장: 기기 지원 방식에 따라 다운로드 또는 이미지 공유.

카드에는 브랜드, 닉네임, 판정, 점수, 순위, 도착 예정일, 계산 시각과 상태를 담는다. 원문·지역·출발지·파일명은 담지 않는다. 모바일 공유 미리보기에서도 핵심 글자가 잘리지 않게 여백을 확보한다.

공유 카드는 생성 당시 스냅샷을 유지한다. 공개 페이지 `/s/[token]`에는 `공유 당시 결과`와 시각을 표시한다. 같은 사용자의 최신 공개 결과를 제공한다면 별도의 명시적 영역으로 표시하고 기존 카드를 조용히 덮어쓰지 않는다.

공개 페이지의 주요 버튼은 `나도 산타컷 받아보기`. 소유자 화면에는 `공유 링크 비활성화`를 제공한다. 서버 링크를 비활성화해도 이미 저장·전달된 이미지를 회수할 수 있다고 표현하지 않는다.

## 5. 오류와 예외 상태

| 상황 | 사용자에게 알릴 내용 | 다음 행동 |
| --- | --- | --- |
| 20MB 초과 | 파일 크기와 허용 크기 | 지원되는 범위로 다시 내보내기 |
| 미지원 형식·스키마 | 지원하지 않는 파일이며 채점되지 않음 | 준비 안내 / 파일 다시 선택 |
| 카톡 본인 식별 불가 | 본인 화자를 확인할 수 없음 | 지원 형식 안내 / 파일 재선택 |
| 최근 기록·근거 부족 | 점수와 순위를 만들 충분한 기록이 없음 | 다른 지원 기록 준비 |
| 닉네임 동시 등록 충돌 | 다른 사용자가 먼저 등록함 | 닉네임만 수정 |
| 업로드 네트워크 실패 | 파일 전송이 완료되지 않음 | 명시적 재시도, 입력 유지 |
| AI 일시 오류 | 이번 심사를 완료하지 못함 | 동일 작업 상태 확인 / 허용 시 재시도 |
| 요청 한도 초과 | 다시 가능한 시점 또는 대기 안내 | 이전 결과 보기 |
| 랭킹 계산 지연 | 마지막 완료 결과의 계산 시각 | 이전 스냅샷 보기 / 새로고침 |
| 세션 만료·쿠키 분실 | 기존 결과 수정 권한을 확인할 수 없음 | 공개 링크 보기 / 새 참여 안내 |
| 시즌 동결 | 이번 시즌 결과와 배송 계획이 확정됨 | 결과 보기 / 확정된 후속 정책 안내 |
| 공유 비활성·존재하지 않음 | 더 이상 볼 수 없는 결과 | 내 산타 점수 알아보기 |
| 삭제 요청 | 삭제 범위·복구 불가 여부 | 확인 후 삭제, 완료 상태 표시 |

빈 데이터나 AI 오류를 0점 결과로 바꾸지 않는다. 오류 시 작성한 닉네임·지역·선택 출처를 가능한 범위에서 유지하되 원본·메시지 본문을 localStorage에 저장하지 않는다.

## 6. 시각·인터랙션 방향

- 분위기: 겨울 우편·산타 심사표. 귀엽지만 점수·날짜는 크게 읽히게 한다.
- 색: 따뜻한 아이보리 바탕, 짙은 녹색 본문·영역, 빨간색 주요 행동. 대비는 실제 색상 확정 후 검사한다.
- 서체: 한국어 가독성 중심의 산세리프. 점수와 날짜 숫자는 폭과 정렬을 일관되게 한다.
- 카드: 결과 카드는 공유 가능한 한 장의 심사표처럼 구성한다. 입력 화면에는 장식을 줄인다.
- 모션: 심사 대기에 짧은 루프, 결과 공개에 한 번의 가벼운 등장 효과. 버튼·내용 접근을 지연시키지 않는다.
- 하단 고정 버튼은 safe area와 키보드를 고려하고 본문을 가리지 않도록 여백을 둔다.
- 터치 영역은 최소 44×44px을 기준으로 한다. 입력 라벨·키보드 포커스·텍스트 오류를 제공하고 색상만으로 상태를 구별하지 않는다.
- 화면 낭독기에 상태 변화를 알리고, 상태 폴링 때마다 포커스를 이동하지 않는다. 페이지 이동 시 제목으로 맥락을 제공한다.

## 7. MVP 우선순위와 구현 단위

### 1차: 입력 흐름 검증

홈, 출처 선택, 준비 안내, 파일 확인, 참가 정보, 분석 확인. 실제 파일 샘플로 사용자가 내보내기부터 본인 화자 선택까지 완료할 수 있는지 확인한다. 준비 절차와 지원 데이터가 검증되기 전 완성된 분석 경험을 약속하지 않는다.

### 2차: 핵심 결과 경험

실제 상태에 연결한 심사 화면, 내 결과, 랭킹, 재심사·지역 변경 제한. 점수·순위·ETA 버전 일치와 경계 상태를 확인한다.

### 3차: 공유와 운영 마감

카드 생성, 공개 페이지, OG 이미지, 링크 비활성화, 내 데이터 삭제, 모바일 공유 호환성과 접근성 확인.

MVP 제외: 친구 초대 리그, 익명 투표, 상세 실시간 산타 지도, 일반 계정·기기 간 복구, 근거 없는 출처별 순위, 배송 최적화.

## 8. 검증할 UX 가설과 측정

| 가설 | 관찰할 지표·행동 |
| --- | --- |
| 등록보다 데이터 준비가 큰 이탈 요인이다 | 출처 선택 → 파일 선택 → 유효 파일 확인 단계별 전환 |
| 결과 예시가 서비스 이해를 돕는다 | 홈 시작률, 사용자가 예상하는 결과를 직접 설명할 수 있는지 |
| 내보내기 안내만 보고 파일을 준비할 수 있다 | 기기별 완료율, 실패 단계, 준비 후 재방문 |
| 점수·순위·도착일이 첫 화면에서 이해된다 | 결과 이해도, 도움말 사용, 다음 행동 선택 |
| 판정과 늦은 도착일이 공유 동기가 된다 | 공유 열기 → 링크 생성 → 복사·기본 공유 호출 성공 |

공유 호출 성공은 실제 게시 완료와 구분한다. 이벤트에는 메시지 본문·파일명·참여자 이름·원본 해시·세션 토큰을 수집하지 않는다. 출처, 단계, 오류 코드, 소요 시간 등 최소 항목만 사용한다.

이탈 원인을 확인할 수 있도록 `start_clicked`, `source_selected`, `guide_opened`, `file_selected`, `file_validation_failed`, `participant_created`, `analysis_requested`, `analysis_succeeded`, `analysis_failed`, `result_viewed`, `share_opened`, `share_link_created` 등을 제안한다. 수집 방식과 동의 정책은 출시 전 확정한다.

## 9. 구현 전 결정할 사항

1. 실제 샘플 검증 후 카톡·인스타 동시 출시 여부와 지원 기기·형식.
   - 결정(2026-11-16): 서버는 카카오톡 PC·iOS·Android TXT와 인스타그램 `message_1.json`을 받는다. zip은 받지 않는다.
   - 파서 정규식은 실제 샘플로 아직 검증하지 않았다. 출시 전에 기기별 실제 내보내기로 확인한다.
2. 준비 우선 흐름 채택 여부. 이 문서의 기본 제안은 파일 준비 후 등록이다.
3. 데이터 준비 안내용 실제 화면과 검증된 외부 링크.
4. 점수 항목·판정 구간, 분석 제공자와 실제 보관 정책.
5. 시즌 동결 이후 신규 참가·재심사의 결과 화면과 안내.
6. 지역 변경 시 기존 공유 링크에서 최신 결과를 제공하는 범위.
7. 서비스명·로고·캐릭터·최종 색상·서체.
