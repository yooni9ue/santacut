# 참가 등록 API 연동

## 실제 등록과 예시 둘러보기

- `/start`의 **참가 정보 먼저 등록·확인하기** 또는 `/join`에서 실제 참가 등록을 시작한다. 실제 파일을 선택한 뒤 참가 정보로 넘어가도 같은 화면이다.
- **파일 없이 예시로 둘러보기**는 기존 화면 체험 경로다. 이 경로의 닉네임·지역 입력은 서버에 등록하지 않는다.
- 실제 파일 선택 뒤에는 동의·업로드·SSE 상태·결과·랭킹 API 흐름을 사용한다. 참가 등록 완료는 분석 완료가 아니다. 연결 범위와 남은 동작은 [화면 안내](screens.md)를 참고한다.

## 호출 흐름

1. `/v1/me`로 세션을 확인한다. 401·404는 미등록 상태로 처리하고, 네트워크·서버 오류는 재시도 안내를 보여준다.
2. `/v1/regions`로 시·도를 불러온다. 하위 지역이 있으면 `?parent=<code>`로 조회하고 `selectable=true`인 코드만 등록한다. 시·도를 변경하면 하위 지역 선택을 비운다.
3. 닉네임은 NFKC 정규화·앞뒤 공백 제거 후 한글·영문·숫자·밑줄 2~16자로 검증한다. 입력이 멈추면 중복 여부를 조회하며 가용성은 예약을 의미하지 않는다.
4. 제출 시 세션과 닉네임 가용성을 다시 확인한다. 공통 Axios가 `/v1/csrf` 응답 본문의 token을 headerName 헤더로 보내고 `POST /v1/participants`를 호출한다.
5. 등록 직후 `/v1/me`로 세션 유지와 참가자 ID를 확인한 뒤 다음 화면으로 이동한다. 이 확인에 실패하면 재등록하지 않고 참가 정보 재조회·쿠키 설정 확인을 안내한다.
6. 다시 `/join`을 열거나 새로고침하면 저장된 참가자를 복원한다. 등록된 닉네임은 수정하지 않으며 같은 정보로 계속할 수 있다.

브라우저는 상대 경로 `/v1`과 `withCredentials: true`를 사용한다. API는 Next.js 프록시를 통해 연결하며 세션·CSRF 토큰을 localStorage에 저장하거나 document.cookie에서 읽지 않는다. 등록은 자동 재시도하지 않는다.

## 검증과 범위

- 단위 테스트: 미등록/서버 장애 구분, 닉네임 정규화와 가용성 쿼리, 지역 쿼리, 등록 오류 안내.
- Chromium·WebKit 모의 API E2E: 실제 등록 본문과 CSRF 헤더, 브라우저 쿠키 복원, 지역 변경과 하위 지역 없는 시·도, 닉네임 충돌, 세션 미유지 시 중복 등록 방지, 세션 조회 실패, 시작 화면 진입.
- 기존 예시 플로우에서 실제 참가 등록 요청이 발생하지 않는지도 확인한다. 모의 테스트의 쿠키는 브라우저 쿠키 저장소로 확인하며 실제 백엔드의 쿠키 전달 검증과 구분한다.
- 실제 개발 서버 통합 검증 결과는 PR에 별도로 기록한다. 테스트 참가자만 생성하며 검증이 끝나면 해당 테스트 참가자만 정리한다.
