# 공개 공유 링크에서 리캡 카드 전체 보기

> 구현 상태(2026-11-27): 백엔드 구현 완료(브랜치 `feat/public-recap-share`). `shares.recap_json` 저장, 링크 재사용 시 한 번 채우기, `/s/{token}` 카드 덱 페이지와 CSP, 테스트까지 반영했다. 실제 모바일 폭·브라우저 확인(완료 기준 7)과 프론트 공유 안내 문구는 아직 남아 있다.

## 목적

결과 화면의 「링크 공유하기」로 만든 링크를 로그인 없이 열었을 때, 기존 점수 요약과 함께 본인에게 제공된 리캡 카드를 순서대로 모두 볼 수 있게 한다. 현재 `/s/{token}`은 공유 시점의 점수·순위 요약과 1200×630 OG 이미지 한 장만 보여 준다. 로그인 사용자용 `GET /v1/me/recap`은 전체 `cards` 배열을 제공하지만 공개 토큰 경로에는 카드가 없다.

범위는 공개 공유 토큰이 가리키는 평가의 리캡 카드다. 산타 조서(dossier)는 이 기능에 포함하지 않는다. 카드 데이터는 링크를 가진 누구나 볼 수 있다는 점을 UI와 공유 안내에 명시한다.

## 현재 계약과 데이터 흐름

- `POST /v1/shares`는 `include_quote`를 받아 `{ token, url, imageUrl }`를 돌려준다.
- `shares` 엔티티는 `snapshot_id`와 점수·판정·순위 등 공유 시점 스냅샷을 저장한다. 리캡 카드 배열은 저장하지 않는다.
- `GET /v1/me/recap`은 `RecapFacade`가 최신 평가, `RoastService` 문장, 순위 스냅샷, 프로필을 조합해 `RecapResponse.cards`를 만든다.
- `/s/{token}`은 `ShareFacade → ShareService → SharePageRenderer`의 서버 HTML이다. 첫 응답에 OG 메타가 있으므로 HTML 크롤러 호환성을 유지해야 한다.
- 프론트는 `NEXT_PUBLIC_API_BASE_URL` 호스트가 아니라 현재 클라이언트 도메인(`/s/{token}`)을 공유 주소로 쓴다. Vercel의 `/s/**` rewrite가 백엔드 HTML/이미지를 프록시한다.

## 권장 구현

### 1. 공유 시점 카드 스냅샷

`shares`에 nullable `recap_json`(또는 명확히 버전이 붙은 `recap_snapshot_json`)을 추가한다. 새 공유 링크 생성 시 서버가 해당 `snapshot.assessmentId`를 기준으로 저장된 팩폭 문장과 동일 평가의 순위·꾸밈 값을 읽어 카드 응답 모델을 만든 뒤 직렬화해 저장한다. 현재 로그인 사용자용 `RecapResponse.from(RecapResult)`의 카드 생성 규칙을 재사용해 두 화면에서 카드 순서와 문구가 달라지지 않게 한다.

`POST /v1/shares` 요청 본문에 카드나 문구를 추가하지 않는다. 클라이언트가 보내는 점수·순위·리캡은 신뢰하지 않는다. 공유할 때 본인 한마디 허용 여부(`include_quote`)는 기존 규칙을 따르며, 새 스냅샷에도 그 선택을 일관되게 적용한다. 같은 평가의 기존 활성 링크를 재사용할 때는 현재 링크에 `recap_json`이 없으면 한 번 채우고 저장한다. 링크 토큰은 유지한다.

스키마 변경은 기존 DB와 테스트 기준 스키마(`backend/src/test/resources/schema-baseline.sql`)를 함께 갱신한다. `ddl-auto: update`로 nullable 컬럼이 추가되는 배포 순서를 확인하고, 기존 행을 강제 백필하지 않는다. 기존 링크는 `recap_json IS NULL`로 유지해 기존 요약 화면으로 폴백한다.

### 2. 공개 페이지

`SharePageRenderer`가 공개 카드 스냅샷을 입력받아 카드 덱을 그린다. 기존 `/s/{token}` 경로·OG 제목/설명/1200×630 이미지·캐시/보안 헤더를 보존한다. 크롤러는 OG 메타를 즉시 읽을 수 있어야 한다. 실제 사람은 첫 HTML에서 카드 첫 장을 보고 전체 목차, 현재 장수, 이전/다음 버튼과 키보드 조작으로 나머지 카드를 볼 수 있어야 한다. 서버 렌더 HTML에 첫 카드와 카드 수를 포함하고, 필요한 경우에만 작은 인라인 스크립트로 넘김을 처리한다. 스크립트가 꺼져도 첫 카드와 정적 목록/본문이 읽혀야 한다.

카드마다 현재 프론트 리캡과 같은 정보 계층(점수, 유형, 제목, 문구, 산타 그림/서명)을 사용한다. 구현은 템플릿 또는 전용 renderer로 두고, 큰 프론트 전용 CSS/React 코드를 서버 HTML에 그대로 복사하지 않는다. `score_text`, 줄바꿈, 날짜, COAL/GIFT 상태 등 카드 종류별 필드가 정확히 렌더되어야 한다. OG 미리보기는 기존 가로형 카드로 유지해도 되며, UI에서 공개 웹페이지의 카드 덱과 OG 이미지가 다른 표현임을 자연스럽게 안내한다.

### 3. 안전한 표시와 노출 범위

- 공유 가능한 카드 응답 필드만 저장한다. 원본 채팅, 상대방 발언, 참가자 이름 목록, 내부 분석 프롬프트, 조서의 비공개 줄은 절대 포함하지 않는다.
- 기본 공유 한마디(`quote`)는 기존 `include_quote=false` 동작을 유지한다. 동의해 실을 때도 현재 백엔드가 정한 본인 한마디만 허용한다.
- HTML 문맥(본문 텍스트, 속성, 스크립트 JSON)에 맞춰 각각 인코딩한다. JSON을 `<script>`에 넣을 때 `<`, `>`, `&`, U+2028/U+2029 및 종료 태그 문자열이 스크립트 경계를 탈출하지 못하도록 직렬화/인코딩한다. 템플릿 문자열을 단순 치환해 JS 문자열을 만들지 않는다.
- 카드 내용은 외부 URL·HTML 태그로 해석하지 않고 텍스트로 표시한다. CSP와 `Referrer-Policy: no-referrer`, `Cache-Control: no-store`를 확인한다.
- 공유 취소 시 기존과 동일하게 토큰과 연결된 페이지/이미지 접근이 차단되어야 한다. 로그에는 토큰이나 카드 문구 전체를 기록하지 않는다.

## API·문서

외부 경로 및 요청 형식은 바꾸지 않는다. `POST /v1/shares`는 여전히 `{ include_quote }`를 받고 같은 응답 구조를 유지한다. `GET /s/{token}`은 HTML을 돌려준다. 공개 HTML에 전체 카드가 보인다는 사실과 링크 보유자 공개 범위를 OpenAPI 설명, `docs/api/frontend-api-guide.md`, 이 문서에 반영한다. 내부 저장 형식은 버전을 넣어 이후 리캡 타입 변경을 감지할 수 있게 한다.

## 완료 기준과 검증

1. 새 공유 생성 시 서버에서 저장한 리캡 카드 수와 순서가 `GET /v1/me/recap`과 일치한다. 브라우저가 카드 내용을 만들어 보내지 않는다.
2. 공유 링크를 다른 브라우저/비로그인 상태에서 열어 모든 카드를 앞뒤로 탐색한다. 카드 제목·점수·서버 문구·장수가 맞는다.
3. 기존 `recap_json=NULL` 공유 링크는 기존 요약 페이지로 열린다. 링크 취소와 없는 토큰은 기존 404 안내 페이지를 반환한다.
4. OG 크롤러 요청에서 HTML 첫 응답에 기존 `og:title`, `og:description`, `og:url`, `og:image`가 있고 JS 없이 메타를 읽을 수 있다.
5. 악성 HTML/스크립트 문자열이 카드 텍스트 필드에 있어도 실행되지 않는다. 고유한 상대 메시지와 비공개 dossier 문자열이 HTML에 나타나지 않는다.
6. 백엔드 단위·통합 테스트: 카드 스냅샷 직렬화/역직렬화, 신규 링크 생성, 기존 링크 재사용 및 스냅샷 백필, 페이지 렌더링·이스케이프·비활성 링크·OG 계약을 확인한다. `./gradlew --no-daemon check bootJar` 통과.
7. 실제 모바일 폭(320px, 390px)과 Chromium/WebKit에서 탐색·접근성을 확인한다. 공유 URL은 개발에서 `https://dev.santacut.me/s/{token}`, 운영에서 `https://santacut.me/s/{token}`이어야 한다.

## 작업 경계

- 백엔드: `Share` 스키마/저장, 링크 발급 시 카드 조립, 공개 페이지 모델/renderer, 관련 OpenAPI·백엔드 문서와 테스트.
- 프론트엔드: 현재 클라이언트 도메인 공유 URL을 유지하고 공유 안내에 모든 카드가 공개됨을 알린다. 개별 PNG 다운로드는 공개 HTML 구현과 독립된 변경이다.
- 운영 배포 전 DB 백업·복구 계획과 백엔드 배포 자동화 결과를 확인한다. develop 배포 후 실제 링크를 다른 브라우저에서 확인한 뒤 운영 릴리스는 별도로 진행한다.
